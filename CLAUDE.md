# sic-povms

- **Merge level: push to `main`.** Claude may push straight to `main` or merge its own PRs.
- **The README is the paper.** Every result must be reproducible and checkable from this repo, without exceptions. Every claim in the README is checkable from this repo, and every number in it comes from a run recorded in a PR. The results are numerical: never call them exact, proved or certified.
- **`fiducials/fiducial_<d>.txt` is written only by `refine.py`, or `refine_2208.py` for d = 2208:** Scott–Grassl layout, 150 digits, unit norm, ψ_0 real and positive, an eigenvector of Scott–Grassl's Zauner unitary (formula and its provenance in `verify.py`). `stark_2208.jl` writes the standard-Zauner 2208 seed. Intermediates (`*_stark.txt`, `*_seed*.txt`) stay untracked.
- **`verify.py` is the independent judge:** it imports nothing from the other scripts and nothing imports it. A new claim about the files gets a check there. Every file in `fiducials/` and `fibonacci/` passes `uv run verify.py` and `uv run verify.py --precise`. Both use row FFTs, O(d² log d) time and O(d) working memory: NumPy in default mode, python-flint at 640 bits (about 192 decimal digits) in `--precise`. Precise deviations and symmetry residuals are numerical upper bounds for the decimal input, compared with 1e-147 before display rounding.
- **`fibonacci/` holds fiducials with Grassl–Scott's Fibonacci antiunitary symmetry F_f (type F_a at d = 2208), not U_Z's.** `fibonacci_2208.py` builds its 2208 seed from a separately fetched, checksummed Grassl–Scott 48g input; `refine_2208.py --output fibonacci/fiducial_2208.txt` writes its published precision. `verify.py` checks F_f, as well as the SIC equations and gauge; CI checks both folders.
- **Adding a dimension:** `julia --project=. stark.jl <d>`, then `uv run refine.py fiducial_<d>_stark.txt`, then both `verify.py` modes; long runs set `STARK_CHECKPOINTS=<dir>` so a killed run resumes. Before the README calls it new, search Grassl's tables, Scott 2017, Bengtsson–Grassl (arXiv:2512.13201), Appleby–Flammia–Kopp (arXiv:2501.03970) and recent arXiv for that d. Update the README's title, counts and dimension lists and, for a `stark.jl` run, add its RESULTS.md row in the same commit.
- **Large dimensions:** separate root scripts may reuse `stark.jl` with empty `ARGS`; each header explains why it departs. External inputs are fetched with a checksum. The README gives rebuild commands with time and peak RSS, tested from a fresh copy without intermediates.
- **Changing `stark.jl`, `refine.py`, `search.py`, the Manifest or the Zauner.jl rev:** regenerate the 14 algebraic d in 197..253 and the standard 2208 file (Julia 1.13.2, one thread) and require `git diff --exit-code fiducials/ fibonacci/`, plus any d the change targets. A changed published file is a new result, so say why in the PR. `stark.jl`'s output must not depend on random state, run order or Hecke's representation of H: its header states the canonical rules, and a change keeps them.
- **Published bytes must not depend on platform, BLAS/LAPACK build or thread count; a new or changed file is rebuilt on a second platform before merge.** Changes to construction or refinement scripts rebuild every affected published file from construction; a saved seed is not a substitute. A changed file is a new numerical result and needs an explanation.
- **Even d:** displacement labels and symplectic matrices live mod 2d (D_(p+du) = ±D_p).
