# sic-povms

- **Merge level: push to `main`.** Claude may push straight to `main` or merge its own PRs.
- **The README is the paper.** Every result must be reproducible and checkable from this repo, without exceptions. Every claim in the README is checkable from this repo, and every number in it comes from a run recorded in a PR. The results are numerical: never call them exact, proved or certified.
- **`fiducials/fiducial_<d>.txt` is written only by `refine.py`, or `refine_2208.py` for d = 2208:** Scott–Grassl layout, 150 digits, unit norm, ψ_0 real and positive, an eigenvector of Scott–Grassl's Zauner unitary (formula and its provenance in `verify.py`). `stark_2208.jl` writes the standard-Zauner 2208 seed. Intermediates (`*_stark.txt`, `*_seed*.txt`, `*_seed*_trial*.txt`) stay untracked.
- **`verify.py` is the independent judge:** it imports nothing from the other scripts and nothing imports it. A new claim about the files gets a check there. Every file in `fiducials/` passes `python verify.py` and `uv run verify.py --precise`.
- **`fibonacci/` holds fiducials whose order-3 symmetry is of type F_a, not U_Z's.** `fibonacci_2208.py` builds its 2208 seed from the bundled, checksummed `fiducial_48g.txt`; `refine_2208.py --output fibonacci/fiducial_2208.txt` writes its published precision. `verify.py` fails them on the U_Z test by design and CI skips them; the README claims no more for them than a recorded run shows.
- **Adding a dimension:** `julia --project=. stark.jl <d>`, then `uv run refine.py fiducial_<d>_stark.txt`, then both `verify.py` modes; long runs set `STARK_CHECKPOINTS=<dir>` so a killed run resumes. Before the README calls it new, search Grassl's tables, Scott 2017, Bengtsson–Grassl (arXiv:2512.13201), Appleby–Flammia–Kopp (arXiv:2501.03970) and recent arXiv for that d. Update the README's title, counts and dimension lists and, for a `stark.jl` run, add its RESULTS.md row in the same commit.
- **Large dimensions:** construction and refinement code stays flat at the root. Separate scripts may reuse `stark.jl` with empty `ARGS` and replace steps that do not fit in memory; each header explains its departures. Pin representative choices and numerical dependencies. Bundle external construction inputs or document a checksummed fetch. The README gives rebuild commands with time and peak RSS measurements for each result. It records the output hashes; test from a fresh copy without saved intermediates. Changes to these scripts must rebuild each affected published file from construction and compare its hash (`refine_2208.py`: both 2208 files). A saved seed is not a substitute for construction code. A changed published file is a new result and needs an explanation.
- **Changing `stark.jl`, `refine.py`, the Manifest or the Zauner.jl rev:** regenerate the 14 algebraic d in 197..253 (Julia 1.13.2, one thread) and require `git diff --exit-code fiducials/`, plus any d the change targets. A changed published file is a new result, so say why in the PR. `stark.jl`'s output must not depend on random state, run order or Hecke's representation of H: its header states the canonical rules, and a change keeps them.
- **Even d:** displacement labels and symplectic matrices live mod 2d (D_(p+du) = ±D_p).
